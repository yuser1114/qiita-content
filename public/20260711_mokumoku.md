# CodexにAGENTS.mdを与えると実装結果はどう変わる？同じ指示で比較してみる

# はじめに

Codexへ同じ機能追加を依頼したとき、`AGENTS.md` の有無と内容の詳しさによって、実装、テスト、変更範囲、完了報告にどのような違いが出るかを比較しました。

# 検証の目的

共通のタスク管理アプリと同じ機能追加指示を使い、次の3条件で実行結果を比較します。

1. `AGENTS.md` なし
2. 最低限の `AGENTS.md` あり
3. 詳細版 `AGENTS.md` あり

# 実施内容

タスクの追加、完了状態の切り替え、削除、未入力拒否を備えた共通アプリを用意しました。各条件では同じ初期状態を使い、それぞれ新しいCodexセッションで同じ機能追加指示を渡しました。

実装後にテスト結果、baselineとの差分、変更ファイル、完了報告を保存し、3条件を同じ基準で評価しました。初期状態のテストは4件です。

## 共通の機能追加指示

```text
タスク管理アプリに、タスクの優先度機能を追加してください。

優先度は「高・中・低」の3種類とし、タスク追加時に選択できるようにしてください。また、登録済みのタスクを優先度で絞り込めるようにしてください。

既存機能を壊さないように実装し、必要な動作確認も行ってください。
```

## 比較条件

| 条件     | AGENTS.mdの内容                                                                  |
| -------- | -------------------------------------------------------------------------------- |
| なし     | リポジトリ内に検証用の指示ファイルを配置しない                                   |
| 最低限版 | 既存コード確認、変更範囲、テスト、Git操作、完了報告を指定                        |
| 詳細版   | 最低限版に加え、ファイル責務、テスト観点、手動確認、結果記録、記事更新方法を指定 |

## 評価項目

要件充足、既存機能の維持、ファイル責務、変更範囲、テスト対応、テスト結果、外部依存、完了報告の8項目を各0〜2点、合計16点で評価しました。

# 実施結果

3条件とも、優先度の選択、一覧上の表示、優先度による絞り込みと解除、不正な優先度の拒否を実装しました。既存の完了切り替え、削除、未入力拒否に関するテストもすべて成功しています。

## 結果の差

- `AGENTS.md` なしではテストを3件追加し、最低限版と詳細版では4件追加しました。
- 最低限版と詳細版では、優先度を省略した場合に「中」になることを個別にテストしました。
- 追加行数は、なし版51行、最低限版63行、詳細版66行でした。
- 要件充足、既存機能、ファイル責務、変更ファイル数、外部依存、無関係な変更、評価点には差がありませんでした。
- 手動確認は3条件とも実施できませんでした。詳細版では指定された11項目を未確認として記録しました。

## 検証上の前提・制約

- 各条件の実行は1回ずつです。
- 条件ごとに新しいCodexセッションを使用しました。
- モデル出力の揺らぎを排除できていません。
- 結果の差が `AGENTS.md` だけによるものとは断定できません。
- 3条件とも環境上の理由によりブラウザでの手動確認を実施できませんでした。

# まとめ

同じ初期状態と同じ機能追加指示を使い、`AGENTS.md` なし、最低限版、詳細版の3条件を比較しました。

3条件すべてで要求機能が実装され、既存機能とファイル責務が維持されました。変更ファイル数はすべて4ファイル、外部依存と無関係な変更はなく、評価はすべて16点でした。

数値上の差は追加・削除行数とテストケース数に現れました。ただし、各条件1回だけの結果であり、モデル出力の揺らぎも排除できていません。
