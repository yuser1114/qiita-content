# Claude Codeに作業依頼していたらセッション制限になったので、Codexと比較してセッション周り深掘ってみる

# はじめに

今回はClaude Codeに同じ実装を依頼して、`CLAUDE.md`の有無や内容によって結果がどう変わるか検証する予定でした。

しかし、検証の途中で初めてセッション制限になりました。

今まで制限を意識せずに使っていたので、急に作業が止まって「セッションって会話のこと？」「いつから使えるの？」「ChatGPTのCodexにも同じ制限があるの？」となりました。

そこで予定を変更して、Claude CodeとChatGPTのCodexについて、利用制限の仕組みと利用量を節約する方法を整理してみます。

なお、利用できる量や継続方法はプラン、モデル、機能などによって変わります。この記事は2026年7月26日時点の公式情報をもとにしています。

# 制限になる前

## Claude Codeの利用制限

Claudeの有料プランでは、ClaudeとClaude Codeの利用量が共有されます。Claude Codeだけを使っていなくても、同じアカウントでClaudeを使った分が影響します。

消費量は単純なメッセージ数ではなく、会話の長さ、添付ファイル、ツールの利用、選択したモデルなどでも変わります。Claude Codeでは、プロジェクトの複雑さやコードベースの大きさも影響します。

ClaudeのUsage画面では、5時間のセッション利用量と週間利用量を確認できます。Claude Codeでは`/status`でも残りの利用量を確認できます。

つまり、「あと何回指示できる」と固定された回数で考えるより、重い作業を続けるほど早く上限に近づくと考えた方がよさそうです。

参考：

- [Use Claude Code with your Pro or Max plan](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)
- [Usage limit best practices](https://support.claude.com/en/articles/9797557-usage-limit-best-practices)
- [Claude Code CLI reference](https://code.claude.com/docs/en/cli-usage)

## ChatGPTのCodexの利用制限

Codexにもプランごとの利用制限があります。

公式情報では、Codexの利用量はエージェント機能の共通枠から消費されます。消費量はタスクの大きさや複雑さ、モデル、実行場所によって変わり、大きなコードベース、長時間のタスク、多くのコンテキストを保持するセッションほど多く消費します。

Claude Codeと同じく、単純に「1メッセージで1回消費」という仕組みではありません。現在の状況や上限到達時の選択肢は、Codexの利用状況画面や表示されるバナーで確認します。

参考：

- [Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

## 制限前の比較

| 比較項目         | Claude Code                              | ChatGPTのCodex                                           |
| ---------------- | ---------------------------------------- | -------------------------------------------------------- |
| 利用量の考え方   | 内容やモデルなどにより変動               | タスクやモデルなどにより変動                             |
| 共有される利用枠 | ClaudeとClaude Codeで共有                | 対象のエージェント機能で共有                             |
| 確認方法         | Usage画面、Claude Codeの`/status`        | Codexの利用状況画面、バナー                              |
| 長い作業の影響   | 会話やコードベースが大きいほど増えやすい | 長時間のタスクや保持するコンテキストが多いほど増えやすい |
| 会話の再開       | `--continue`、`--resume`を利用できる     | 同じタスクで会話を継続できる                             |

両方とも、メッセージ数だけを数えていれば上限を予測できるわけではない点は共通していました。

Claudeは5時間のセッションと週間利用量がUsage画面に分かれて表示されるため、「セッション制限」という言葉が表に出やすい印象です。

Claudeの画面で`Day`と表示されていても、リセットまでの残り時間が併記されている場合は、暦日ではなく現在の5時間枠を指します。表示時刻になると、使った分が徐々に戻るのではなく、5時間枠の利用量がリセットされます。

Codexにも同様に5時間の短期利用枠があります。ただし、別の上限や共有の利用枠が適用される場合もあるため、実際のリセット時刻や利用可能量は各サービスの利用状況画面を確認するのが確実です。

# 利用量の節約術

## Claude Codeでできること

Claude Codeには、利用量を抑えるための具体的な方法が公式ドキュメントにまとめられていました。

### タスクが変わったら`/clear`する

長い会話では、過去のメッセージや読み込んだファイルも後続のやり取りでコンテキストとして扱われます。

別のタスクへ移るときに`/clear`を実行すると、`CLAUDE.md`やプロジェクトファイルは残したまま会話履歴を空にできます。関係のない過去のやり取りを引き継がないため、公式では利用量と回答品質の両方に効果が大きい方法として紹介されています。

ただし、消した会話履歴は元に戻せません。後で必要になりそうな内容は先に保存しておく必要があります。

### 同じタスクを続けるなら`/compact`する

作業途中で会話履歴を消せない場合は、`/compact`でこれまでの内容を短く要約できます。

`/compact APIの変更点とテスト結果を残す`のように、残してほしい内容も指定できます。Claude Codeには自動的なコンパクト機能もありますが、会話が長くなったと感じた段階で実行すれば、不要なコンテキストを早めに減らせます。

### ファイルを貼り付けずパスを伝える

ファイル全体をプロンプトへ貼ると、その内容が会話のコンテキストに残ります。

Claude Codeはローカルファイルを読めるため、コードを貼り付ける代わりにファイルパスと対象の関数名を伝えた方が、必要な箇所を選んで確認できます。ログも全文ではなく、関係する行だけを渡す方法が推奨されています。

### タスクに合ったモデルとeffortを選ぶ

複雑な設計や原因が分からない不具合と、単純な修正では必要な推論量が異なります。

公式情報では、一般的な実装にはSonnet、難しい判断にはOpus、機械的な作業にはHaikuという使い分けが紹介されています。また、単純な作業ではeffortを低くすると、推論に使うトークンを減らせます。

常に高性能なモデルと最大のeffortを使うのではなく、難しい部分だけ切り替えるのがよさそうです。

### 不要なツールや並列実行を減らす

Web検索やResearch、MCPなどのツール利用も消費量に影響します。使っていないMCPサーバーは無効にし、必要なときだけ有効にした方がコンテキストを減らせます。

また、サブエージェントやAgent Teamsはそれぞれ独立したコンテキストを持つため、数を増やすほど利用量も増えます。並列化すれば必ず節約になるわけではなく、独立して進める価値がある作業だけに使う必要があります。

利用状況は`/usage`、現在のコンテキストの内訳は`/context`で確認できます。感覚だけで節約するのではなく、何がコンテキストを使っているか確認できるのは便利そうです。

参考：

- [Models, usage, and limits in Claude Code](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)
- [Manage costs effectively](https://code.claude.com/docs/en/costs)
- [How do usage and length limits work?](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)

## Codexでできること

Codexについては、Claude Codeのように節約用コマンドを並べた公式情報は確認できませんでした。

ただし、公式ヘルプでは、タスクの大きさと複雑さ、モデル、実行場所、コードベースの大きさ、実行時間、保持するコンテキストによって消費量が変わると説明されています。

この説明から、次の方法は利用量を抑える方向に働くと考えられます。

- 一つの依頼へ関係のない作業をまとめない
- 大きな作業は目的が明確な単位へ分ける
- 対象のファイルや変更範囲を先に指定する
- 単純な作業に必要以上に重いモデルや高い推論量を使わない
- 長いタスクを続ける前に利用状況を確認する

ただし、これらはCodexの公式ヘルプに「節約術」として列挙されているものではありません。公式に説明されている消費量の要因から考えた対策です。

## 節約術の比較

| 方法 | Claude Code | ChatGPTのCodex |
| --- | --- | --- |
| 不要な会話履歴を減らす | `/clear`、`/compact`がある | 長いセッションほど消費が増えるという説明あり |
| 入力を絞る | ファイルの貼り付けを避け、パスを指定 | 対象や変更範囲を絞るのがよさそう |
| モデルを使い分ける | `/model`で変更できる | モデルにより消費量が変わる |
| 推論量を調整する | effortを変更できる | 利用できるモデルでは推論量を選択できる |
| ツールを整理する | 不要なMCPなどを無効化できる | 実行内容を必要な範囲に絞る |
| 消費状況を確認する | `/usage`、`/context` | 利用状況画面、バナー |

具体的な節約方法はClaude Codeの方がドキュメント化されていました。Codexでも依頼を小さく明確にすることは有効そうですが、どれだけ節約できるかは今回実測していません。

# 制限になった後

## Claude Codeで制限になった後

公式情報では、上限に達した後の主な選択肢は次のとおりです。

- 利用枠がリセットされるまで待つ
- プランで利用できる場合は追加の利用クレジットを有効にする
- Claude Consoleの従量課金へ切り替える
- 継続的に不足する場合はプランを変更する

追加クレジットやAPIの従量課金は、サブスクリプションに含まれる利用量とは別です。とりあえず表示された選択肢を進めるのではなく、課金方法を確認してから選ぶ必要があります。

利用枠が戻った後は、保存されているClaude Codeのセッションを再開できます。直近の会話なら`claude --continue`、特定の会話なら`claude --resume`を使用できます。

今回のような比較検証では、制限中に別条件だけ別のAIで続けず、同じ環境と同じAIで再開する方が比較条件を維持できます。

## Codexで制限になった後

Codexでは、実行中のターンで利用上限に達しても、そのターンはフェアユースの範囲で継続できると公式に説明されています。

そのターンが終わった後は、プランに応じて次のような選択肢を利用状況画面やバナーで確認します。

- リセットを待つ
- 利用できる場合はクレジットを追加する
- 利用できるリセットを適用する
- プランを変更する

すべてのプランで同じ選択肢が出るわけではないため、実際に表示された内容を確認する必要があります。

## 制限後の比較

| 比較項目         | Claude Code                         | ChatGPTのCodex                     |
| ---------------- | ----------------------------------- | ---------------------------------- |
| 基本的な対応     | リセットを待つ                      | リセットを待つ                     |
| 追加利用         | クレジットや従量課金など            | 対象プランではクレジット追加など   |
| 上限到達中の処理 | 警告後、上限到達時に継続方法を選ぶ  | 実行中のターンは一定条件で継続可能 |
| 再開             | 保存済みセッションをCLIから再開可能 | 同じタスクから継続可能             |
| 注意点           | API利用へ切り替えると別料金         | 選択肢はプランによって異なる       |

# 制限前にやっておきたいこと

今回初めて制限に達して、途中で止まる可能性を前提にしていなかったことに気づきました。

次からは以下を意識しようと思います。

- 作業開始前に利用状況を確認する
- 長い検証は条件ごとに結果を保存する
- 実行した指示、変更差分、テスト結果をリポジトリへ残す
- 一つの会話へ関係のない作業を詰め込みすぎない
- 比較実験では途中でAIやモデルを変えない
- 追加クレジットや従量課金を使うか事前に決めておく

特に比較検証では、最後にまとめて記録するのではなく、1条件が終わるごとに結果を保存することが大切そうです。制限だけでなく、通信エラーやPCの再起動が起きても再開しやすくなります。

# 制限になった後に確認すること

制限になった場合は、次の順番で確認すると落ち着いて判断できそうです。

1. 会話のコンテキスト上限ではなく、プランの利用制限なのか確認する
2. 利用状況画面でリセット時刻や残りの利用量を確認する
3. 実行途中の変更とテスト結果を保存する
4. 待つ、追加利用する、別作業へ切り替えるのどれにするか決める
5. 比較条件が変わらない方法で作業を再開する

別のAIへ切り替えれば作業自体を続けられる場合もあります。しかし、今回のようにAIの動作を比べる検証では、切り替えることで検証条件が変わってしまいます。

「作業を終わらせること」と「同じ条件で検証すること」のどちらを優先するかで、制限後の対応を変える必要がありそうです。

# まとめ

今回はClaude Codeで初めてセッション制限に到達したことをきっかけに、ChatGPTのCodexと利用制限を比較しました。

Claude CodeとCodexは、どちらも作業内容やモデルなどによって消費量が変わり、単純なメッセージ回数だけでは上限を予測できません。また、制限後はリセットを待つ以外に追加利用の選択肢が用意される場合がありますが、プランや課金方法の確認が必要です。

節約方法を調べてみると、Claude Codeではタスクが変わったときの`/clear`、同じタスクを続けるときの`/compact`が基本になりそうです。ファイルを貼りすぎないことや、モデル、effort、ツールを作業に合わせて選ぶことも利用量の削減につながります。

Codexは具体的な節約手順がClaude Codeほど明示されていませんでしたが、対象範囲を絞り、長く複雑なタスクを避けることが利用量を抑える方向に働くと考えられます。

今回予定していた`CLAUDE.md`の比較は、利用枠が戻ってから同じClaude Codeの環境で続きを実施しようと思います。
