# はじめに

最近プロジェクトで使われる用語が多く、覚えられずにいて困っています！
雰囲気で推測できたりはするが、直接関係ない用語はスルーしてしまっています。。。
そこで今回は、アジャイル開発・スクラム・プロジェクト管理系の用語を改めて復習していきます！！

# 用語一覧

ChatGPTに一覧で用語を出してもらいました。
それぞれテーマ別に出してくれたので、見ていきます。

## 作業単位・チケット系

「スパイク」以外は割と聞いていて、意味も理解できていました！

| 用語                            | 意味                                                        |
| ------------------------------- | ----------------------------------------------------------- |
| Epic / エピック                 | 大きな機能・大きな開発テーマ                                |
| Feature / フィーチャー          | 機能単位。Epic より小さいまとまりとして使われることが多い   |
| PBI                             | Product Backlog Item の略。プロダクトバックログ上の作業項目 |
| User Story / ユーザーストーリー | 「誰が、何のために、何をしたいか」で表す要件                |
| Task / タスク                   | 実装・調査・修正などの具体的な作業                          |
| Sub-task / サブタスク           | タスクをさらに分割したもの                                  |
| Bug / バグ                      | 不具合修正のチケット                                        |
| Spike / スパイク                | 技術調査・検証用の作業                                      |
| Issue / イシュー                | 課題・問題・作業チケットの総称                              |
| Ticket / チケット               | Jira や Backlog などで管理する作業単位                      |

## バックログ・優先順位系

言い回しは違えど、なんとなく理解できていました。
ただ「マイルストーン」がなんのためにあるのかいまいちだったので聞いてみました。
　⇒「一言でいうと、プロジェクトが順調に進んでいるかを確認するためです。」
作業者目線だとそこまで気にしていなかったのでためになりました。

| 用語                       | 意味                                         |
| -------------------------- | -------------------------------------------- |
| Product Backlog            | 今後やること一覧。機能・修正・改善などが入る |
| Sprint Backlog             | 今回のスプリントでやること一覧               |
| Backlog Refinement         | バックログの整理・詳細化・見積もり           |
| Priority / 優先度          | どれを先にやるか                             |
| Severity / 重大度          | バグや問題の影響度                           |
| Roadmap / ロードマップ     | 中長期の開発計画                             |
| Milestone / マイルストーン | 節目・中間ゴール                             |
| Release Plan               | いつ何をリリースするかの計画                 |

## スクラムイベント系

アジャイル・スクラム開発を去年から初めてやるようになって、嫌でも覚えたので理解できていました。
今の現場が1週間スプリントで、毎週レトロをやっていてKPTそれぞれ思いつかなくて苦労していたので、改めて聞いてきました。
　⇒「レトロの目的は「反省会」ではない。次の1週間を少しだけ良くする会です。毎回KPTをがっつり埋める必要はないです。」
毎週金曜日の午前に頭を抱えながらなんか良いとこと悪いとこなかったかなって探していたので、
これからは反省よりは来週に向けてどうしていこうって目線で考えようと思います！

| 用語                               | 意味                               |
| ---------------------------------- | ---------------------------------- |
| Sprint / スプリント                | 1〜4週間程度の短い開発期間         |
| Sprint Planning                    | スプリント開始時の計画会           |
| Daily Scrum / Daily Standup        | 毎日の進捗確認会                   |
| Sprint Review                      | 完成したものを関係者に見せる会     |
| Retrospective / レトロスペクティブ | 振り返り会。改善点を話す           |
| Refinement / リファインメント      | チケットの内容を整理・明確化する会 |

## スクラムの役割系

ここの用語は聞いていたけど、全然意味というか役割を認識してませんでした。。。
これからLDの立場になる可能性があるので、それぞれの役割を改めて認識していこうと思います。

| 用語                  | 意味                                   |
| --------------------- | -------------------------------------- |
| Product Owner / PO    | 何を作るか、優先順位を決める人         |
| Scrum Master / SM     | スクラムがうまく回るよう支援する人     |
| Development Team      | 実際に開発するチーム                   |
| Stakeholder           | 利害関係者。依頼者、利用部門、顧客など |
| Project Manager / PM  | プロジェクト全体の進行管理をする人     |
| Product Manager / PdM | プロダクトの価値・方向性を考える人     |

## 完了条件・品質系

PRとかで目にはしていて、一回は調べたことがあったけどあんまり認識できてない。。
口に出したり聞く機会が少ないと思うので、覚えられなそう。。。

| 用語                               | 意味                                              |
| ---------------------------------- | ------------------------------------------------- |

| Definition of Done / DoD           | 完了と判断できる状態の定義                        |
| Done / 完了                        | 実装・テスト・レビューなどが終わった状態          |
| MVP                                | Minimum Viable Product の略。最小限の価値ある製品 |
| Increment / インクリメント         | スプリントごとに増える完成済み成果物              |

## 開発手法・管理手法系

今の現場で「イテレーションレビュー」ていう毎週決まった日に打ち合わせがあって、
話す機会もほとんどないからあんまり意識してなかった。
ChatGPTに聞いて見ると「スプリントレビュー とほぼ同じ意味で使われることが多い」とのことで。
「スプリントレビュー」は、以前の現場で自分主体でやっていたこともあったので、改めてイメージできました！

| 用語                           | 意味                                               |
| ------------------------------ | -------------------------------------------------- |
| Agile / アジャイル             | 小さく作って、確認しながら改善する開発スタイル     |
| Scrum / スクラム               | アジャイル開発の代表的な進め方                     |
| Kanban / カンバン              | タスクを「未着手・作業中・完了」などで流す管理方法 |
| Waterfall / ウォーターフォール | 要件定義→設計→実装→テストのように順番に進める開発  |
| Iteration / イテレーション     | 短い開発サイクル。スプリントに近い                 |
| Lean / リーン                  | 無駄を減らして価値提供を早くする考え方             |
| DevOps                         | 開発と運用を連携させて継続的に改善する考え方       |
